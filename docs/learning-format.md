# Формат обучения

## От теории к практике

Каждый модуль начинается с короткого объяснения темы и примеров из задач QA. После теории студент выполняет упражнения: пишет типизированные данные, разбирает асинхронный код, создаёт тесты или улучшает их структуру. Материал строится последовательно, поэтому модули лучше проходить по порядку.

Не пытайтесь запомнить всё после первого чтения. Возвращаться к примерам и официальной документации нормально. Повторение одних и тех же приёмов в следующих модулях — часть обучения.

## Из чего состоит модуль

В каждом модуле есть четыре страницы:

- **обзор** — цель, теория, примеры и практические QA-сценарии;
- **домашнее задание** — пошаговая работа и ожидаемый результат;
- **чеклист** — конкретные вопросы для самопроверки перед PR;
- **ресурсы** — официальная документация и необязательные дополнительные материалы.

## Где выполняется практика

Домашние задания выполняются в отдельном [репозитории домашних заданий](https://github.com/EugeneChirkun/Pw-Ts-Qa-Hw), а не в репозитории сайта курса. Студент работает в ветке текущего модуля, предварительно обновляет её из личной ветки `student/{student-name-slug}/master` и отправляет решение через pull request (PR) в эту личную ветку.

## Что проверяется на ревью

Ревью отвечает не только на вопрос «работает ли решение». Проверяются также:

- понятные названия и читаемый код;
- логичная структура файлов;
- отсутствие лишнего дублирования;
- устойчивость тестов и удобство их поддержки;
- результаты проверки типов и применимых тестов.

Замечания — это продолжение практики. Их нужно разобрать, исправить в той же ветке и повторно выполнить проверки.

## На чём основаны примеры

Курс использует знакомые QA-задачи: тестовые пользователи и тест-кейсы, проверку форм и навигации, анализ падений, UI- и API-сценарии. Акцент сделан на вопросах «как» и «почему»: как написать тест, почему локатор должен быть стабильным, зачем нужен Page Object Model и когда использовать fixture.
